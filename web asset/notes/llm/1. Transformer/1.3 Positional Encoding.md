### 1. 为什么需要位置编码
传统的循环神经网络（RNN）、卷积神经网络（CNN）等在处理序列数据时，会“自然”地保留序列信息：

- RNN 一次只接收一个时刻的输入，顺序地从左到右（或右到左）处理，这就天然地包括了序列顺序的信息。
- CNN 通过卷积核在局部范围进行扫描，也能保留相对顺序或位置信息。

> 这其实是一种 inductive bias，限制了以上模型的优化空间
> 
> “**Inductive bias（归纳偏置）**” 是机器学习中的一个核心概念，指的是：
> 
> **在没有足够数据的情况下，模型对“合理假设”的倾向或偏好。**
> 
> 简单说就是：**模型在学习时默认的“先验信念”**。这种偏置帮助模型在面对不完整信息时做出更靠谱的推理。
> 
> 在 RNN 和 CNN 中，**序列的顺序是模型结构天然带来的偏置（inductive bias）**：
> 
> - RNN 是按顺序一个一个处理的，自带“时间”概念。
>     
> - CNN 用卷积核在局部滑动，有“位置”的概念。
>     

然而，Transformer 中使用的 **自注意力机制（Self-Attention）** 并没有内在的顺序概念。它在计算attention时，可以并行地关注序列中任意位置的词或符号，而不会像 RNN 那样严格按照时间步展开，也不像 CNN 那样局部扫描。**也就是说，自注意力机制是与位置无关的。**

However，位置非常重要！
在自然语言处理任务（如机器翻译、文本生成等）或其他序列任务（如时间序列分析等）中，词或特征的出现顺序往往至关重要。例如句子“我爱你”和“你爱我”尽管包含了相同的词，但它们含义完全不同。

- 如果不显式地告诉模型“第一个 token 是谁，第二个 token 是谁，第三个 token 是谁……”，模型在进行自注意力时就无法利用序列顺序信息。
- 因此，在 Transformer 中引入一个**位置编码（Positional Encoding）**，用来在特征表示中打上每个 token 在序列中所处位置的信息。

> The idea of positional encoding
	**位置编码（Positional Encoding）** 就是给每个输入 token（或符号）添加一个向量，用来表示其在序列中的位置（或顺序）。

- 这个向量可以看作是一种信号，与 token 的词向量或特征向量相加或拼接在一起，从而让后续的自注意力机制知道每个 token 的位置信息。
- 对于常见的 Transformer 实现来说，位置编码的维度与词向量的维度相同，这样可以直接与词向量做相加操作，不用额外增加模型的层数或参数维度。

**关键点：** 位置编码本质是一种 *把序列位置注入特征表示”* 的方法。

主要有一下几种positional encoding的方式：
在 Transformer 模型中，主要有以下几种位置编码方法：

- **绝对位置编码（Absolute Positional Encoding）**
    - **固定的正余弦位置编码（Sinusoidal Positional Encoding）**
    - **可学习的位置编码（Learnable Positional Embedding）**
        
- **相对位置编码（Relative Positional Encoding）**
    - **旋转位置编码（Rotary Position Embedding, RoPE）**
    - **ALiBi (Attention with Linear Biases)**


#### 1.1 Sinusoidal Positional Encoding
这是 **《Attention Is All You Need》** 论文中提出的经典方法。他们并没有选择让位置编码成为可训练的参数，而是设计了一套基于正弦和余弦函数的**确定性**计算方法。这样做的好处是：

- 如果序列长度在训练时没见过，模型依然可以通过插值或外推的方式，保持同样的正弦和余弦规律，从而处理比训练时更长的序列。
- 与可学习的嵌入相比，不会额外引入大量可训练参数。

```txt
= [1.54, 0.64, -0.35, 1.6, 0.4, 1.1]    ← 最终的输入向量
```

##### Benefit
- 可插值性： 因为是sin和cos，**所以当序列位置>训练位置的时候**，*位置编码依旧可以顺着正弦和余弦的周希后推*，模型也可以一定程度上理解这个位置信息。
- **平滑性**：随着$position$的逐渐增加，编码向量的变化是平滑连续的，没有跳跃。
- **无额外参数**：所有参数均是按照固定公式生成，不会额外增加可学习的权重。


#### 1.2 Learnable Positional Embedding
如果我们允许位置编码在训练的过程中进行“学习”，那么就像词向量（word embedding）一样，模型可以自己通过训练数据来决定如何在不同的维度上表示位置信息。这个方法相比正余弦公式更加“灵活”，但也有一些潜在问题，例如：
- 训练可能需要更多数据，才能覆盖更长的序列范围。
- 如果需要处理的序列长度超过训练时的最大长度，模型对超长序列的位置索引就没法很好地extrapolate.

![[Pasted image 20260821221642.png|361]]
具体点来说，就是：
把位置向量当作模型的**参数**，和词向量一样随机初始化，然后靠训练数据反向传播慢慢学好。
- 模型里存一张"位置表"：位置 1 一个向量、位置 2 一个向量……一直到位置 512
- 每个位置查表取向量，就像词向量查表一样
- BERT、GPT 系列用的就是这种方式

具体的计算就是:
1. 第一条：初始化矩阵 P

$$P \in \mathbb{R}^{L_{max} \times d_{model}}$$

这就是一个**二维表格**：
- **行数 = $L_{max}$**：预先设定的最大序列长度，比如 512。每一行对应一个位置：第 0 行是"位置 0 的向量"，第 1 行是"位置 1 的向量"……
- **列数 = $d_{model}$**：每个位置向量的维度，必须和词向量维度一致（这样才能相加）

举个例子，$L_{max}=512$、$d_{model}=768$（BERT base 的配置），那么 P 就是一个 512×768 的矩阵，约 39 万个参数，**随机初始化**，一开始里面的数值没有任何意义。

2. 第二条：查表取向量

> 对于序列中的第 position 个 token，其位置编码就是 P[position] 这一行向量。

这和词向量的用法**完全同构**：

```
词表 E：  token "dog"  → 查 E[dog的id]   → 得到词向量
位置表 P：位置 1      → 查 P[1]         → 得到位置向量
```

回到我们的例子："dog" 在 position = 1，就去 P 里抽出第 1 行，得到一个 768 维（图例里是 6 维）的向量，加到词向量上。

对比一下正弦方案：那里是"拿公式现算"，这里是"查表"。效果类似，但来源不同——一个是数学家写死的，一个是模型自己学的。

3. 第三条：训练时像词向量一样更新

> 训练过程中，这个矩阵 P 会像词向量一样，随着反向传播更新。

这是关键：**P 是可训练参数**。每次反向传播，梯度不仅更新词向量表、注意力权重，也更新 P 的每一行。训练结束后：

- 位置 0 的那一行，学到了"句首"意味着什么
- 相邻位置的行会变得相似（模型自己学到了"位置 5 和位置 6 关系近"）
- 具体学成什么样，完全由数据和任务决定，没有人为设计的结构

```
"dog" (position=1)
   │
   ├─ E[dog_id]→ [0.7, 0.1, -0.4, ...]   ← 词表查行（可学习）
   │
   ├─ P[1] → [0.0, -0.1, -0.3, ...]  ← 位置表查行（可学习）
   │
   └─ 相加 → 送入 Transformer

训练中：E 和 P 都跟着反向传播一起更新
```

#### 相对位置编码 （Relative Position Encoding）
在某些任务中，尤其是文本中，需要捕捉 token 之间**相对**的顺序或距离信息（如“前面 3 个词”、“后面 2 个词”），而不仅仅是 token 相对于序列起点的位置

这个想法的核心就是： 给距离分配向量，而不是位置

#### 主角： RoPE （Rotary Position Embedding）
解决了注意里计算中如何高效且连续的embed position information, 他不给向量加位置，而是添加旋转的角度, this beautifully merge with rotation on complex plain 

> Detail: 

先看最简单的情况：一个 2 维向量。因为**乘上 $e^{i\theta}$ 等价于在平面上旋转角度 θ**（模长不变，只转方向）。
RoPE 的做法是：位置为 $m$ 的 token，它的 Q 向量和 K 向量各旋转 $m\theta$ 度：

$$f(q, m) = q \cdot e^{im\theta}$$

直观画面：
```
位置 0 的向量：  →          （不转）
位置 1 的向量：  ↗          （转 θ）
位置 2 的向量：  ↑          （转 2θ）
位置 3 的向量：  ↖          （转 3θ）
```

同一个词 "dog"，在位置 1 和位置 5，向量内容一样，但**朝向不同**。

![[Pasted image 20260821225008.png|308]]

##### 妙处：相对位置自动从点积里"冒出来"
回忆注意力的打分是点积 $q \cdot k$。两个旋转后的向量做点积：

$$f(q, m) \cdot f(k, n) = q \cdot k \cdot e^{i(m-n)\theta}$$

看最后那项：$e^{i(m-n)\theta}$——**只依赖距离 m−n，不依赖绝对位置 m 和 n！**

几何直觉：两个向量都顺时针多转 30°（比如整个句子往后挪），它们的**夹角不变**，点积也不变。所以点积天然只反映"相对位置"。

##### 所以，假如是高维怎么办：分成一对一对地转

$d_{model}$ 维向量没法直接"转"，RoPE 的做法是把它切成 $d/2$ 个 2 维小块，**每对维度独立旋转**，而且每对用不同的角速度 $\theta_i$：

$$\theta_i = 10000^{-2i/d_{model}}$$

这和正弦位置编码的频率公式**一模一样**。不是巧合，RoPE 可以看作正弦编码的"旋转版"：

| | 正弦编码 | RoPE |
|---|---|---|
| 频率设计 | 不同维度不同频率 | 不同维度对不同角速度 |
| 注入方式 | **加**在输入向量上 | **乘**（旋转）在 Q、K 上 |
| 位置体现 | 绝对位置 | 相对距离（自动涌现） |


低频的维度对转得慢（捕捉远距离关系），高频的转得快（捕捉近距离关系），分工和正弦编码同理。

实际计算时不用复数，每对维度 $(x, y)$ 乘一个 2×2 旋转矩阵：

$$\begin{pmatrix} x' \\ y' \end{pmatrix} = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix} \begin{pmatrix} x \\ y \end{pmatrix}$$

就是展开来两组 sin/cos，计算量很小。

#### ALiBI (Attention with Linear Biases)
它的思路是所有方案里**最激进也最简洁**的：*干脆不做位置向量了。*

ALiBi 认为：模型需要的不是"知道每个词在第几个位置"，只是一个归纳偏置（inductive bias, **"离得近的词更相关"**。那就直接把这个先验写进注意力分数。

##### 原理：按距离扣分
原始注意力打分：

$$\text{score}(Q, K) = QK^\top / \sqrt{d_k}$$
ALiBi 在上面加一个线性惩罚项：
$$\text{score}(Q, K) \;{+}{=}\; -\alpha \times \text{distance}$$

- `distance` = key 和 query 之间的距离（相隔几个词）
- $\alpha$ 是一个正的斜率常数（原论文用固定值，不用训练；每个注意力头用不同的斜率，有的头惩罚陡、只看很近的词，有的头平缓、能看很远）

举例：query 是 "dog"，它看不同 key 时：
```
chased（距离 1）：分数 - α×1     ← 稍微扣点
pig   （距离 3）：分数 - α×3     ← 扣得多
The   （距离很远）：分数 - α×N    ← 几乎被压没
```

> 所以Alibi的外推能力很强， 因为ALiBiA只是加上了一个线性的距离惩罚，可以不断衍生
