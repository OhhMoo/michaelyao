### 1. 什么是 mask(掩码)
![[Pasted image 20260822221341.png|295]]

主要目的：在multi-head attention机制的计算当中，屏蔽掉某些不可见或不相关的位置，从而保证模型的correctness and accuracy。 

具体在transformer中的意义就是：
1. **限制信息泄露（Information Leakage）** 在自回归语言模型或解码阶段的自注意力中，如果允许模型访问未来的词（token），就会造成“信息泄露”（model 看到尚未生成的词），从而导致不正确的预测或训练信号。通过 mask，可以屏蔽掉未来时刻的词，使得模型只能依赖历史信息进行预测。
2. **避免无关位置的干扰**： 对于批量数据（batch）中不同长度的序列，常需要使用 Padding 来对齐输入长度。Padding 位置实际上并不包含任何有效信息，为避免在注意力计算中干扰模型，需要用 mask 将这些位置屏蔽掉。
3. **训练目标需要**： 例如在 BERT 中，引入 "**遮挡语言模型（Masked LM）**" 任务，需要将输入序列中部分 token 用 `[MASK]` 或随机 token 替换，并让模型预测原始 token。这就需要相应的 mask 机制来指示被替换或被屏蔽的部分。
4. **其他自定义需求**： 一些高级变体（如 span masking、跨模态 masking 等）也会根据具体任务（机器翻译、图像字幕生成、多模态学习等）自定义 mask，用于控制模型关注的范围或引入先验知识。


### 2. Mask的具体使用方法
#### 2.1 Core Formula

$$\text{Attention}(Q, K, V) = \text{Softmax}\left(\frac{QK^T}{\sqrt{d_k}} + M\right)V$$

这就是**缩放点积注意力（Scaled Dot-Product Attention）**，它是多头注意力的基本单元。这里的重点在于做完dot-product和scaling之后，加上了一部 **$+\,M$， 加上 Mask 矩阵**
- 所以，**Mask 矩阵**形状与得分矩阵 $QK^T$ 相同：`(batch_size, num_heads, seq_len, seq_len)`

#### 2.2 Mask 是怎么起作用的
关键在于：**Mask 是在 Softmax 之前加到得分上的**。
- **要屏蔽的位置**：令 $M_{ij} = -\infty$（实际代码里用一个很大的负数，比如 $-10^9$）。经过 Softmax 后，$e^{-\infty} \to 0$，这些位置的注意力权重**趋近于 0**——模型就"看不见"这些 token 了。
- **要保留的位置**：令 $M_{ij} = 0$。加 0 不改变得分，注意力正常计算。
- 这样就可以保留特定的位置，并让softmax remove剩下的不要的位置

#### 2.3 使用场景
1. **Padding Mask（填充掩码）** --> 一个 batch 里的句子长度不同，短句补上的 padding 位置没有实际意义，需要屏蔽掉，防止模型关注它们。
2. **Causal Mask（因果掩码 / 上三角掩码）** --> GPT 这类自回归模型在预测第 i 个 token 时**不能"偷看"未来的 token**，所以把得分矩阵的上三角（j>i 的位置）全部置为 −∞ ，保证预测只依赖已经出现的词。

### 3. 架构和mask的关系
因为**同一个注意力公式、同一套 Mask 零件，仅仅是堆叠方式和掩码图案不同，就决定了模型能干什么** --> 所以，架构之争 ≈ 掩码图案之争 ≈ "哪些 token 已知、哪些待生成"这个问题的三种回答。

![[Pasted image 20260822223756.png|398]]
具体来说，在这张图里, 
- **每一行** = 一个 token 作为"查询者"（当前正在处理的 token） 
- **每一列** = 一个 token 作为"被关注者"（key）
- **黄色方块** = 允许关注（Mask 里是 0 的位置）
- **空白** = 被屏蔽（Mask 里是 −∞ 的位置） 
整个网格就是前面说的 M 矩阵的可视化。

##### 1. Causal Decoder（因果解码器）
输入 "I am a causal decoder"，5 个 token。注意力矩阵是**下三角**：
- "I" 只能看 "I"（1 个方块）
- "am" 能看 "I, am"
- "a" 能看 "I, am, a"
- ……每个 token 只能看**自己和之前**的 token

这就是我们之前说的**下三角 Mask**：右下角全被 −∞ 封死。原因还是那个，因为生成时不能偷看未来，因为未来还没生成出来。

##### 2. Non-causal Decoder（非因果解码器）
同样一条流水线，但把开头几个 token（这里是 "I am"）当作**已知的条件信息（prefix）**，对它们**双向关注**：
- 左下那个 2×2 的实心方块："I" 和 "am" 之间可以**互相看**（包括"往后看"），因为它们是已知条件，不存在"泄露未来"的问题
- 后面的 token（"a", "NC", "decoder"）仍然是因果的，但可以**完整看到整个前缀**
应用：你有一个给定的上下文（比如问题、文档），希望模型充分消化它（双向），再逐词生成回答。

##### 3. Encoder-Decoder（编码器-解码器）
这里模型被**劈成两半**，注意横轴标注：前两个 token 走 **Encoder**，后面的走 **Decoder**：
- **Encoder 部分**（"I am"）：2×2 实心方块，**双向自注意力**，充分理解输入
- **Decoder 部分**（"an encoder decoder"）：
    - 对所有 encoder 输出的关注是**完整的矩形块**——解码时每个词都能看到全部编码结果（这就是 cross-attention）
    - 对 decoder 自身的关注仍是**下三角**——自己生成的部分还是得保持因果


### 4.  Transformer的mask
#### 4.1 mask的具体分类
**第一类：注意力 Mask**（加在 QKT 得分上的那个 M ，决定"**谁能看见谁**"
- Padding Mask：屏蔽补齐的空位
- Causal / Look-Ahead Mask：屏蔽未来位置
- Cross-Modal / Segment Mask 等变体：同一思想的其他形状

**第二类：训练任务 Mask**（MLM Mask， 决定"**预测谁、算谁的损失**"
- BERT 的做法是把输入里的 token **替换成 `[MASK]`**（输入层面的遮挡），并且**只对被遮住的位置算损失**（损失层面的屏蔽）。它通常**不是**加在注意力分数上的矩阵。这是个常见混淆点，教材这一节的标题叫 Mask，但 MLM 的"遮"和前两种不是一个位置发生的事。

#### 4.2 Padding Mask
since 神经网络的批量训练要求一个 batch 里所有序列**形状相同**，才能拼成一个大矩阵在 GPU 上并行算。但真实句子的长度不一样：

```
句子 1："我 爱 学习"           → 3 个 token
句子 2："今天 天气 很 好 呀"    → 5 个 token
```

解决办法：以 batch 内最长长度（这里是 5）为准，短句后面**补齐（Padding）**——通常填 0 或一个特殊的 `<PAD>` token：

```
句子 1："我 爱 学习 <PAD> <PAD>"   → 对齐成 5 个位置
句子 2："今天 天气 很 好 呀"        → 本来就是 5 个
```

问题随之而来：**`<PAD>` 位置没有任何语义，但注意力机制不知道这一点。** 如果不处理，"我"在计算注意力时也会给 `<PAD>` 分一份权重（Softmax 会强行把概率分给它），这份权重乘上 Value 就是纯噪声，污染了表示。

> Padding Mask 就是把这个噪声位置封死

做法完全符合我们之前说的 Mask 机制：在 $QK^T$ 得分矩阵里，**凡是 key 位置（列）是 padding 的，就把那一列填成 $-\infty$**（工程上是 `-1e9` 这种大负数）。
比如：
$$
M = \begin{bmatrix}
0 & 0 & 0 & -\infty & -\infty \\
0 & 0 & 0 & -\infty & -\infty \\
0 & 0 & 0 & -\infty & -\infty \\
0 & 0 & 0 & -\infty & -\infty \\
0 & 0 & 0 & -\infty & -\infty
\end{bmatrix}
\quad \leftarrow \text{后两列（第 4、5 个 token）是 padding，整列封死}
$$

注意它是**按列封**的：屏蔽的含义是"**谁都不许关注 padding 位置**"，而不是"padding 自己不许看别人"。

过 Softmax 之后，每一行的权重就只会分配在前 3 个真实 token 上，比如 $[0.5, 0.3, 0.2, 0, 0]$——`<PAD>` 拿到精确的 0，对输出毫无影响。

##### 它在三种架构里出现在哪
- **Encoder 自注意力**：必须有（所以 BERT 双向理解时不会去看 `<PAD>`）
- **Decoder 自注意力**：必须有（和 Causal Mask 合并）
- **Cross-Attention**：源序列（encoder 那边）如果有 padding，也要封——所以 decoder 的每个词只关注源句子的真实内容

#### 4.3 Casual Mask
想象 GPT 在生成 "I am a causal decoder"：它必须**一个词一个词地往外吐**——生成第 3 个词时，第 4、5 个词**根本还不存在**。

这里有个微妙之处：训练的时候，完整句子其实是已知的（训练语料就摆在那），模型会把整个序列**并行**地一次性算完（这叫 teacher forcing，训练效率极高）。但如果不在注意力里做手脚，第 2 个位置就能"看到"第 3、4、5 个 token——等于考试直接抄答案。训练时作弊爽了，推理时未来不存在，模型就崩了。

所以需要一个机制：**训练和推理行为一致，位置 $i$ 永远只能依赖 $1 \dots i$。** 这就是 Causal Mask。

##### Implementation
下标 $(i, j)$ 的含义：**第 $i$ 个 token（query 方）能否看到第 $j$ 个 token（key 方）**。

$$
M_{ij} = \begin{cases} 0, & j \le i \quad \text{（过去和现在：放行，得分不变）} \\ -\infty, & j > i \quad \text{（未来：封死，Softmax 后权重归零）} \end{cases}
$$

对长度 $L=5$ 的序列，写出来就是：
$$
M = \begin{bmatrix}
0 & -\infty & -\infty & -\infty & -\infty \\
0 & 0 & -\infty & -\infty & -\infty \\
0 & 0 & 0 & -\infty & -\infty \\
0 & 0 & 0 & 0 & -\infty \\
0 & 0 & 0 & 0 & 0
\end{bmatrix}
$$
- **第 1 行**："I" 只能看自己（1 个 0）
- **第 3 行**："a" 能看 "I, am, a"（前 3 个）
- **第 5 行**：最后一个词能看全部

对照教材那句话："上三角矩阵（或下三角，视实现而定）", 被**封死**的是上三角；有些教材按"可见区域"描述所以说下三角。就是之前那张三种架构图左列的三角形。

这也是为什么transformer比rnn快这么多，因为不是在follow time sequence，而是使用mask然后进行matrix multiplication


#### 4.4 MLM Mask
首先MLM和casual和padding不是同一个层面的东西！

| | Padding / Causal Mask | MLM Mask |
|---|---|---|
| 作用位置 | 注意力**得分矩阵**上（$M$ 加到 $QK^T$ 里） | **输入层**（改 token）+ **损失层**（选位置） |
| 目的 | 控制"谁能看见谁" | 制造一个**训练任务**：猜被遮住的词 |
| 属于 | 模型结构的一部分 | 预训练任务的设计 |

##### MLM 在干什么：完形填空式预训练
BERT 不是生成模型，它不预测"下一个词"，它的预训练任务是**做完形填空**：
```
原句：  "我 爱 学习 机器 学习"
遮挡后："我 爱 [MASK] 机器 学习"
任务：  根据上下文猜出 [MASK] 处是"学习"
```

随机遮掉约 15% 的 token，让模型从左右两边的上下文把被遮的词猜回来。为了猜得准，模型被迫学会深度的双向语义理解——这就是 BERT 理解能力强的来源。

##### 具体做法的三步
**第 1 步：输入替换。** 被选中的 token 不是简单删掉的（删掉会改变序列长度），而是做替换。BERT 实际用的是 80/10/10 策略：被选中的 token 里 80% 换成 `[MASK]`、10% 换成随机词、10% 保持不变——这是为了缓解"训练时有 `[MASK]`、下游任务没有"的不一致。

**第 2 步：注意力里通常不屏蔽 `[MASK]` 位置。** 这是教材特意强调的反直觉点：`[MASK]` 位置**仍然参与注意力计算**——它需要主动从其他位置收集信息（它是 query），其他位置也需要能看它。真正的答案藏在**嵌入层**：`[MASK]` 的输入向量是"我不知道这里是什么"的占位符，模型看不到原词，必须靠上下文推理。

**第 3 步：损失只算被遮的位置。** 没被遮的词模型不需要猜（输出是什么无所谓），损失函数只统计 `[MASK]` 位置的预测误差。这也是一种"mask"，但作用在**损失函数**上，不是注意力矩阵上。

##### 2 variations
- **Span Mask（整段遮挡，BART 用）**：不遮单个词，而是遮**连续的一段**（比如 "我 [MASK] 学习"，中间 "爱 机器" 整段没了），甚至用一个特殊 token 顶掉整段。难度更大——模型既要猜内容还要猜长度，学到的恢复能力更强，适合生成任务。
- **Permuted LM（XLNet）**：想兼得两家之长——既想像 GPT 那样有自回归的生成能力，又想像 BERT 那样利用双向上下文。做法很巧：**随机打乱预测顺序**（随机排列），再用**注意力 Mask** 来实现"每个位置只能看到排列中在自己之前的 token"。注意：XLNet 的 Mask 又回到了注意力矩阵层面，但图案是**随机的、由排列决定的**，不再是固定三角形。


### 5. 什么是encoder & decoder self atttention
##### self-attention definition
"自"指的是 **Q、K、V 来自同一个序列**——序列自己关注自己。
```
输入序列 "我 爱 学习"
     ↓ 分别乘三个权重矩阵
Q, K, V 全部来自这同一个序列
     ↓
每个词和"自己家"的所有词算相似度 → 互相交换信息
```

回忆一下之前的对应：如果是 **Cross-Attention（交叉注意力）**，Q 来自 decoder 的序列，K、V 来自 encoder 的序列——是"两个不同序列之间"的关注。而 self-attention 是"一个序列内部"的关注。

Encoder self-attention 和 decoder self-attention 都是"自"注意力，公式一模一样，**区别只在两件事：作用的对象是谁、加什么 Mask。**

##### Encoder Self-Attention（编码器自注意力）
**作用对象**：输入序列（已知内容，比如待翻译的英文句、待分类的评论）
**Mask**：只有 Padding Mask → **双向关注**
举例，输入 "The cat sat"：

```
"The" 可以看 "cat" 和 "sat"
"cat" 可以看 "The" 和 "sat"     ← 每个词都能看所有词
"sat" 可以看 "The" 和 "cat"
```

**为什么可以这么"开放"**：整句话已经全部摆在这了，不存在"未来"的概念，让每个词充分吸收全句信息，理解才够深。比如 "cat" 看到后面的 "sat"，才确定自己在这里是主语动物而不是别的意思。

**产出**：每个 token 一个"充分理解了上下文"的表示向量，交给下游（分类头、或者 encoder-decoder 里的 decoder）。

##### Decoder Self-Attention（解码器自注意力）
**作用对象**：正在生成的输出序列（比如翻译到一半的译文、GPT 写到一半的回复）
**Mask**：Causal Mask + Padding Mask → **只能看左边**
举例，正在生成 "我 爱 ---"：

```
"我" 只能看 "我"
"爱" 能看 "我"、"爱"
第 3 个位置 能看 "我"、"爱"、自己   ← 第 4 个位置还没生成，绝对不许看
```

**为什么必须这么"封闭"**：decoder 的工作就是**预测下一个词**。如果训练时让位置 $i$ 看到 $i+1$ 及以后，等于把答案贴在考卷上；推理时未来根本不存在，行为必须一致。
**产出**：每个位置一个表示，用来预测下一个 token。

所以，两者大概是这种：

| | Encoder Self-Attention | Decoder Self-Attention |
|---|---|---|
| 处理什么序列 | 输入（已知、完整） | 输出（正在生成） |
| Q、K、V 来源 | 同一个**输入**序列 | 同一个**输出**序列 |
| Mask | Padding | Padding + Causal |
| 关注方向 | 双向 | 只能看左边 |
| 目的 | 理解 | 生成 |
| 典型用户 | BERT、encoder-decoder 的 encoder | GPT、encoder-decoder 的 decoder |
- **Encoder-only（BERT）**：只有 encoder self-attention
- **Decoder-only（GPT）**：只有 decoder self-attention
- **Encoder-Decoder（T5/翻译模型）**：两种都有——encoder 用第一种读懂输入，decoder 用第二种逐词生成，中间再用 cross-attention 把 decoder 的 Q 接到 encoder 的输出上
